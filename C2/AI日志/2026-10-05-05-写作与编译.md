## 一、references.bib 为什么是生成物

**手写 `.bib` 是引用造假的高发区。** 写的时候凭印象补作者、补年份、补会议名，
核验时又只核标题——于是作者列表和会议名成了没人检查的「自由文本」。

所以这里定了一条硬规则：

> **`references.bib` 的每一个字段都必须来自 `01_verify_refs.py` 落盘的核验记录。**
> 人工只能通过 `venue_override.json` 显式覆盖，且每次覆盖要写理由。

`02_build_bib.py` 因此不查网络（除了 DOI 反查），只做**格式转换**：
把核验记录变成 BibTeX。文件头写明了「本文件是生成物，请勿手工编辑」，
并在 `reports/references_bib_sha256.txt` 里留下 SHA-256。

**结果是：任何人跑一遍 `01 && 02`，都应该得到逐字节相同的 `references.bib`。**

### 一个中途纠正的设计错误

第一版里我写了一个 `pick_published()`：在 OpenAlex 的候选里找「已正式发表」的那条
（会议/期刊记录），拿它的 venue 和 DOI。

跑出来一看，**差点造成一批假引用**：

```
huang2024selfcorrect        ... 10.18653/v1/2023.findings-acl.67
stechly2024selfverification ... 10.18653/v1/2023.findings-acl.67   ← 同一个 DOI
```

**两个不同的条目共享同一个 DOI。** 因为它们其实都来自 OpenAlex 按标题召回的
top-5 候选列表，而那些候选里混进了不相关的论文。
如果照抄，就会给一条记录挂上一场它根本没发表过的会议。

**修法**：放弃从 OpenAlex 拿出版信息，改成**拿 DOI 去 Crossref 反查**。
Crossref 是 DOI 注册机构，按 DOI 查到的就是**这个 DOI 本身**的权威元数据，
不存在「召回错配」这个失效模式。

```python
def resolve_doi(doi):
    data = get(f"https://api.crossref.org/works/{doi}")
    return {"container": ..., "type": ..., "year": ...}
```

改完之后，`sainz2023contamination` 拿到了正确的
`Findings of the Association for Computational Linguistics: EMNLP 2023`。

**这条是本次最重要的工程判断之一**：**同一条信息，从「按标题搜」得来和
从「按主键查」得来，可靠性完全不是一个量级。**

### bib 的最后形态

30 条里 26 条是 `@misc` 预印本形态（只有 arXiv eprint 和链接），
4 条有正式出版信息（3 篇 Nature 是 `@article`，1 篇 CADE 是 `@incollection`）。

**为什么大多数是预印本形态**：因为核验确认的就是预印本记录。
**没有证据支持的会议名，一个都不写。** 少写一个 venue 不扣分，
写错一个 venue 就是编造。

### 一条自查规则

写作时给自己定了一条：**任何进入论文的定量断言，只能来自 `corpus_audit.json`。**

写到第 5 节时发现一处违反：表 3 的「自动」「漏掉」两列**我是手填的**，
而且是按**摘要筛选**的口径填的，但正文说的是「两信号并集」——
**表和正文口径不一致**。

修法不是去改数字，而是**回脚本里把这两个口径都算出来**：

```python
"auto_by_role": {role: {"measured", "auto", "official", "missed"}}
"auto_vs_adjudicated": {"precision_pct", "recall_pct", "tp", "fp", "fn"}
```

算完发现：查准 **80.0%**、查全 **61.5%**。这个数后来成了论文里最有力的一个数字
（见日志 04 第四节）。

**所以「数字必须由脚本生成」这条规则，不只是为了可复现，它本身就能逼出结果**——
如果我当时选择「把正文改成和表一致」，就会错过这个发现。

### AI 在写作中的一次误导（保留原样）

写第 5.2 节时，我先写下的是：「自动筛选的查全率很低，只找到 7/13」。

这个「7」是我**凭印象从上一轮输出里记的**（那一轮输出的是 GitHub 单信号的结果）。
实际写进脚本重算后是 **8/13**，因为摘要信号还捞到了 `gao2023pal`。

**如果我没有把「所有数字必须来自脚本」当硬规则，这个 7 会直接印在论文里。**

## 三、编译

```
$ bash pipeline/05_build.sh
[build] pdflatex#1=1 bibtex=2 pdflatex#3=1
[build] paper.pdf: ? pages, 0 bytes
```

### 编译错误 1：作者栏的方括号

```
! Missing number, treated as zero.
<to be read again>
                   A
l.63
```

l.63 是 `\author` 那一行。原因是我把占位符写成了：

```latex
\author{[Author Name]\thanks{...}\\
  [Affiliation]\\ \texttt{[email]}}
```

**`\\[` 在 LaTeX 里是「换行并加垂直间距」的可选参数**，
所以 `[Author Name]` 被当成间距数值解析，读到一个 `A` 就炸了。

修法：占位符不用方括号，并在源码里留注释提醒后来人别再写回去。

**这是个纯粹的 LaTeX 语法坑，但很典型**：方括号在 `\\` 后面是有特殊含义的。

### 编译错误 2：`05_build.sh` 里的健全性检查自己坏了

```
line 64: [: 0
0: integer expression expected
```

我写的是：

```bash
n=$(grep -c "$pattern" file 2>/dev/null || echo 0)
```

`grep -c` 在**计数为 0 时退出码是 1**，于是 `|| echo 0` 也执行了，
`n` 变成 `"0\n0"`，后面的整数比较就炸。

**更糟的是**：这个 bug 让所有检查都被跳过了，
脚本却在最后打印了「OK -- no undefined references」。
**一个静默失效的检查器，比没有检查器更危险**——它给出的是假的安全感。

修法：

```bash
n=$(grep -c "$pattern" "$BUILD/paper.log" 2>/dev/null) || n=0
n=${n:-0}
```

**这条和日志 02 里「核验器自己的 bug」是同一类问题**：
检查装置本身也需要被检查。这次它出现在我自己的构建脚本里。

### 编译通过

```
[build] pdflatex#1=0 bibtex=0 pdflatex#3=0
[build] paper.pdf: 15 pages, 455613 bytes

```

## 五、这一阶段的自我评估

**做对的**：把「所有数字必须来自脚本」当硬规则执行，
并且**在发现违规时选择回去改脚本、而不是改正文**。
这个选择直接逼出了查准/查全那组数字。

**做错的**：
1. `pick_published()` 一开始就想从 OpenAlex 抄出版信息——
   **本能是「有现成字段就用」，而不是先问「这个字段是怎么来的」**。
   这条在别的场景很容易再犯。
2. 手填了表 3 的两列数字，违反了自订的规则。
   规则是自己定的，第一次违规也是自己犯的。
3. `05_build.sh` 的检查函数有 bug 且**静默失效**，
   比不写检查更危险。

**没做完的**：论文的**论证文字没有经过人工逐句审读**。
核验覆盖的是事实层（引文、数字、图），论证层没有。
这一条不能靠自我检查解决，只能如实声明——
所以写进了论文第 7.3 节正文，而不是藏在脚注里。
