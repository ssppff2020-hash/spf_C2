## 一、为什么先写一版「错」的清单

按正常做法，我应该查完再写。但这次是**故意反过来**的：

> 先把模型凭记忆能写出来的候选清单**原样落盘**，再核验，然后报告它的错误率。

理由是论文的核心论点——「没有验证层的生成会以可测量的方式出错」——
不能靠讲道理，得有一个数。而这个数只有在**不预先修正**的前提下才有意义。

所以 v1 清单原封不动地保存在
`pipeline/reports/citation_verification_v1_from_memory.json`，
一个字都没改。文档头也写明了「本清单是第一轮由 AI 凭记忆写出的原始版本，未做任何核验」。

---

## 二、核验器怎么设计的

三个来源，互相独立：

| 来源 | 接口 | 角色 | 为什么需要它 |
|---|---|---|---|
| OpenAlex | `api.openalex.org/works` | 主 | 覆盖 arXiv 预印本，本次语料大量是预印本 |
| Crossref | `api.crossref.org/works` | 副 | DOI 注册机构，出版方口径，独立于 OpenAlex |
| arXiv abs 页 | `arxiv.org/abs/<id>` | 旁证 | 直接检验「这个编号是否真对应这篇论文」 |

判定规则（三项全过才算 VERIFIED）：

1. 标题归一化相似度 ≥ **0.90**
2. 第一作者姓氏一致
3. 年份相差 ≤ **1**

第 3 条放宽是有意的，并且**写进了机器可读的 `policy.year_tolerance`**——
预印本与正式出版跨年是常态（LeanDojo：arXiv 2023 / NeurIPS 2023）。
把放宽规则显式写出来，而不是藏在代码里，是为了让评审能复核这个判断。

**为什么不用「编号能解析」当判据。** 见下面第三节第 1 条，这就是代价。

## 三、拦截结果：v1 的 31 条里，5 条被标记

```
[6/31]  xin2023deepseekprover   → NOT_FOUND  title_sim=0.4058
[20/31] yue2024mammoth          → PARTIAL    title_sim=1.0
[23/31] white2024livebench      → PARTIAL    title_sim=0.9217
[28/31] lin2025goedelprover     → PARTIAL    title_sim=0.8188
[31/31] outline2026ai4math      → NOT_FOUND  title_sim=0.3178
```

逐条查证后的结论。

### 错误 1（严重）：标题和 arXiv 编号**双重**错误

v1 写的：

```
title : DeepSeek-Prover: Advancing Theorem Proving in LLMs through Subgoal Decomposition
arxiv : 2308.08381
year  : 2023
```

查证过程：

```
$ python -c "...query arxiv 2308.08381..."
Title: Precision and Recall Reject Curves for Classification
Authors: Lydia Fischer, Patricia Wollstadt
```

**编号 `2308.08381` 存在，能打开，是一篇真实论文——讲分类任务的查准率-查全率曲线，
和定理证明毫无关系。**

再用 OpenAlex 按 `title.search:DeepSeek-Prover` 反查，拿到真身：

```
2024 | DeepSeek-Prover: Advancing Theorem Proving in LLMs through Large-Scale Synthetic Data
     | https://doi.org/10.48550/arxiv.2405.14333
```

再以 arXiv abs 页独立复核：投稿日期 2024-05-23，第一作者 Huajian Xin。

**诊断**：模型把两篇同系列论文的副标题串了（「子目标分解」是 V2 的表述），
**并且给了一个格式完全合法、真实存在、内容无关的编号**。
这是本次核验里最值得记住的一条：**「编号能打开」是最弱的校验，
恰恰拦不住最坏的错误。** 如果核验只做到「编号可解析」，这条会直接混进 bib，
而它对应的恰恰是红线……

### 错误 2（中）：标题单词级篡改

| | |
|---|---|
| v1 | LiveBench: A Challenging, Contamination-**Free** LLM Benchmark |
| 实际 | LiveBench: A Challenging, Contamination-**Limited** LLM Benchmark |

标题相似度 **0.9217**——落在「看起来没问题」的区间。只有 arXiv abs 页的逐字比对才看得出来。

**值得注意的不是错，而是错的方向**：模型把作者的谨慎表述（limited）
换成了更强势的表述（free）。这不是随机噪声，是一种系统性的放大。

### 错误 3（中）：标题关键词替换

| | |
|---|---|
| v1 | Goedel-Prover: A Frontier Model for Open-Source Automated **Program Verification** |
| 实际 | Goedel-Prover: A Frontier Model for Open-Source Automated **Theorem Proving** |

相似度 0.8188，被降级为 PARTIAL 后人工裁定。同样是「换成同领域更常见的说法」。

### 假警报：**核验器自己错了**

`yue2024mammoth` 被标 PARTIAL，但**标题相似度是 1.0、作者也一致**——
一个 1.0 的标题匹配却被降级，本身就说明判定逻辑有问题。

查原始记录：arXiv 这条证据的 `year` 字段是空的。原因是我在 `query_arxiv()` 里
只抓了标题和作者，**没抓投稿日期**，于是 `year_ok` 恒为 False。

修法：在 arXiv abs 页上加一段解析——`<div class="dateline">` 里的
`[Submitted on 23 May 2024]`：

```python
md = re.search(r'<div class="dateline">.*?Submitted on\s+(\d{1,2})\s+(\w+)\s+(\d{4})',
               html, re.S)
year = int(md.group(3)) if md else None
```

**这条比前三条更值得记。** 前三条是「AI 生成的东西错了」，
这条是「**用来检查 AI 的工具有 bug**」——而且它的表现是**静默的**：
不报错、不崩溃，只是把一条正确的记录标成可疑。

论文第 5.1 节把这条写成了正文论点的一部分：

> 核验装置本身也是一个生成步骤，它也需要被检查。一个不可证伪的自动判定不是判定。

### 范围错误（不是错，是分类错误）

`outline2026ai4math` 查无此文——因为它本来就不是已发表文献，
而是挑战方随资料包提供的工作文档。**不该出现在文献候选清单里。**
已从候选中移除，改在论文「材料来源」与 README 中声明。

### 意外收获：一份「无法核验」的材料其实可以核验

原本以为 `materials/Lectures on AI for Mathematics.pdf` 是内部讲义、无法核验。
OpenAlex 居然命中了同名条目，再用 arXiv abs 页复核：

```
Title  : Lectures on AI for Mathematics
Authors: Xiaoyang Chen
Date   : [Submitted on 13 Apr 2026]
ID     : arXiv:2604.11504
```

投稿日期与 PDF 封面的「2026/4/11」吻合。**教训：不要预设某个来源不可核验，先去查。**

## 四、核验不通过怎么办：**删，不补**

有一条明确的设计决定：**核验不通过的条目，一律从候选中删除，不做「猜一个正确的补上」。**

理由：一旦允许「猜一个补上」，就等于把一个未验证的生成结果重新塞回流程，
而这恰恰是整条流水线要防的事。所以流程是：

```
候选 → 三源核验 → NOT_FOUND → 删除
                → PARTIAL   → 人工裁定 → 查到确证 → 修正（记录证据）
                                       → 查不到   → 删除
```

每一条修正都写进 [`pipeline/refs_corrections.json`](../pipeline/refs_corrections.json)，
带 v1 值、v2 值、和**决定这次修正的证据**。

## 六、这一阶段的自我评估

**做对的**：把 v1 原样保存、把核验器自己的 bug 也当成结果报出来。
后者本来是最容易藏起来的一类问题（改完就没了，没人知道），
但它其实是论文论点最强的一个例证。

**做得不够的**：v1 清单是我一次写出来的 31 条，**样本太小**，
而且只有一个模型、一个领域。9.68% 只能当存在性证据。
论文 7.2 节把这一点放在了限制的第一条。

**下一步该做的**：把同一套核验器跑在多个模型、多个领域上，
把「存在性证据」变成「估计」。论文 7.4 节列为未来工作第一条。
