## 二、编译健全性检查

`pipeline/05_build.sh` 会检查五类问题，**任何一类出现即以退出码 1 失败**，不会静默通过：

| 检查 | 匹配模式 | 本次结果 |
|---|---|---|
| 未定义交叉引用 | `LaTeX Warning: Reference .* undefined` | 0 |
| 未定义引文 | `LaTeX Warning: Citation .* undefined` | 0 |
| 未定义控制序列 | `Undefined control sequence` | 0 |
| 紧急停止 | `Emergency stop` | 0 |
| 找不到文件 | `! LaTeX Error: File` | 0 |

> **关于这个检查器本身**：它的第一版有 bug——`grep -c` 在计数为 0 时退出码为 1，
> 导致 `n=$(grep -c ... || echo 0)` 产出 `"0\n0"`，整数比较报错，
> **所有检查被跳过，脚本却仍然打印了 "OK"**。
> 一个静默失效的检查器比没有检查器更危险，因为它给出的是假的安全感。
> 已修复（`n=$(...) || n=0`），修复过程记在
> [`AI日志/2026-10-05-05-写作与编译.md`](../AI日志/2026-10-05-05-写作与编译.md) 第三节。

## 六、两台机器上的可复现性说明

| 层面 | 是否可复现 | 说明 |
|---|---|---|
| 论文章节结构、字数、页数 | ✅ | 只要宏包齐全，版式一致 |
| `references.bib` 内容 | ✅ | 内容哈希可逐字节复现（前提：上游索引未变） |
| 论文中的**全部数字** | ✅ | 由 `03_corpus_audit.py` 从落盘 API 响应重算 |
| 三张插图 | ✅ | 由 `04_make_figures.py` 从同一份 JSON 重算 |
| `paper.pdf` 字节 | ⚠️ | 内嵌时间戳不同，哈希会变 |
| 上游索引的**当前状态** | ⚠️ | OpenAlex/Crossref/GitHub 的数据会变；本研究记录的是 2026-10-05 的状态，原始响应已落盘在 `pipeline/reports/` |

**最后一条需要特别注意**：`01_verify_refs.py` 每次跑都会**重新查一次上游**。
如果几年后某个索引改了记录，重跑的结果可能与本文不同。
所以 `reports/citation_verification.json` 不是缓存，**是当时的证据快照**，应当以它为准。

## 七、编译中修正的两个错误

留档，因为它们都是可复现的坑。

### 错误 1：`! Missing number, treated as zero.`

```
! Missing number, treated as zero.
<to be read again>
                   A
l.63
```

`paper.tex` 第 63 行是 `\author` 块。原因是占位符用了方括号：

```latex
\author{[Author Name]\thanks{...}\\
  [Affiliation]\\ \texttt{[email]}}
```

`\\[` 在 LaTeX 中是「换行并加垂直间距」的可选参数，
所以 `[Author Name]` 被当作间距数值解析，读到 `A` 就报错。

**修法**：占位符去掉方括号，并在源码里留注释提醒后来人。
（作者栏已在提交前填写为 `\author{Songpengfei\thanks{...}}`，源码顶部的 `TODO(author)` 注释随之替换。）

### 错误 2：构建脚本的健全性检查静默失效

见本文第二节的说明。
