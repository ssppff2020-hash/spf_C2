## 二、逐句对照发现的三个风险（开工时就识别出来的）

1. **红线「引用造假」⇒ 引用必须机器核验，不能靠「我查过了」。**
   → 直接决定了 `01_verify_refs.py` 必须先于写作存在。

2. **红线「不可编译 ⇒ ≤5 分」⇒ 先建环境再写论文。**
   → 本机一个 TeX 都没有，所以第一件事是装 TeX Live（见日志 03）。

3. **任务书自己列出可接受的贡献形态 ⇒ 不必追求理论突破。**
   → 选题落在「分类 ＋ 对比实验 ＋ 清单」，而不是「证明一个新定理」。

## 三、本轮新增的一列：**完成度**

C1 的对照表只打勾。C2 的复盘发现，**「打勾」这件事本身不够**——
C1 的 F6（用 AI 翻译替代「机翻＋人工校对」）在旧表里也是「✅」，
因为「有没有做」通过了，但「做到了什么程度」没被检查。

所以本表加了一列**完成度**，并且**逐条写实际完成到什么程度**，而不是打勾。
上表中唯一标 ⚠️ 的那一条，就来自这一列。

## 四、唯一一条部分完成的（如实标注）

**验收要点第 4 条：「文中所有『AI 生成结论』均有人工核验记录」**

| 层面 | 是否核验 | 方式 |
|---|---|---|
| 事实层：引用 | ✅ | 三源交叉核验，逐条留证 |
| 事实层：数字 | ✅ | 全部由脚本从落盘数据生成 |
| 事实层：图与表一致性 | ✅ | 图与表读同一份 JSON |
| 事实层：可编译性 | ✅ | `05_build.sh` 三趟编译 ＋ 五类检查 |
| **论证层：第 3 节的推理** | ❌ | **无人工逐句审读** |
| **论证层：第 7 节的讨论与外推** | ❌ | **无人工逐句审读** |

**严格按字面读**：「AI 提出了一个四段链框架」也是一个 AI 生成的结论，
所以验收要点第 4 条要求它也有核验记录，而它没有。

**处置方式（不藏）**：

1. 写进论文正文 **7.3 节**，而不是藏在脚注或 README 里：
   > What is *not* verified is the argumentative prose. No human has
   > line-by-line audited the reasoning in §3...
2. 写进 [`核验/论据对照表.md`](论据对照表.md)，用证据等级 **C** 明确标出
   第 3、6、7 节的论断属「论证」而非「事实」，读者应按论证标准检验。
3. 写进 `README.md` 第六节「方法说明」的「未被验证的部分」。
4. 写进 [`AAR`](../AAR/C2-七维复盘AAR.md) 失败清单 **F6**，并给出改进动作。

**为什么选择声明而不是掩盖**：C1 复盘的结论是——
F6 之所以是最该记住的一条，是因为当时**用了一个更容易实现的近似替换了字面要求，
并且在心里把它合理化了**。这次是同一类错误换了形式（把「核验」默认成「核验事实」）。
区别在于：这次在交付前就被识别出来，并且写进了正文。
**「没做到的那部分，要自己先说」——这是 C1 复盘留下的最重要的一条。**
