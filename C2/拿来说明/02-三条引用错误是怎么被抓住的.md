# 拿来说明 02 · 三条引用错误是怎么被抓住的

> **一句话**：三条错误里，只有一条能被「编号能不能打开」这种弱校验拦下——
> 而它恰恰是**最危险的那一条却拦不住**。三条全靠**逐字比对标题**才抓出来。

---

## 一、背景

论文红线的第一条是「引用造假 → 研究严谨性 0 分」。
所以引用核验不是「抽查一下」，而是整个交付流程的前置条件。

**设计决定**：候选引用**先让模型凭记忆写出来，原样落盘，再核验**。
理由有二——一是能测出生成步骤的真实错误率（Study A），
二是避免「边查边改」把错误率抹平。

## 二、核验判据

三项全过才算通过：

| # | 检查项 | 阈值 |
|---|---|---|
| 1 | 标题归一化相似度 | ≥ 0.90 |
| 2 | 第一作者姓氏 | 一致 |
| 3 | 年份 | 相差 ≤ 1 |

三源交叉：OpenAlex（主）、Crossref（副）、arXiv abs 页（旁证）。

## 三、31 条里被标记的 5 条

```
[6/31]  xin2023deepseekprover  → NOT_FOUND  title_sim=0.4058
[20/31] yue2024mammoth         → PARTIAL    title_sim=1.0
[23/31] white2024livebench     → PARTIAL    title_sim=0.9217
[28/31] lin2025goedelprover    → PARTIAL    title_sim=0.8188
[31/31] outline2026ai4math     → NOT_FOUND  title_sim=0.3178
```

**5 条标记 → 3 条真实错误 ＋ 1 条核验器自身 bug ＋ 1 条分类错误。**

---

## 四、错误 1：编号合法、能解析、指向完全无关的论文

### 模型写出来的

```
title : DeepSeek-Prover: Advancing Theorem Proving in LLMs through Subgoal Decomposition
arxiv : 2308.08381
year  : 2023
```

### 核验产出

抓 arXiv abs 页 `2308.08381`：

```
Title  : Precision and Recall Reject Curves for Classification
Authors: Lydia Fischer, Patricia Wollstadt
```

**这个编号存在、能打开、是一篇真论文——讲分类任务的查准率-查全率曲线。**

### 真身

OpenAlex 按 `title.search:DeepSeek-Prover` 反查，再以 arXiv abs 页独立复核：

```
Title : DeepSeek-Prover: Advancing Theorem Proving in LLMs through Large-Scale Synthetic Data
arXiv : 2405.14333
Date  : [Submitted on 23 May 2024]
Author: Huajian Xin
```

### 对比

| | v1（模型写的） | v2（核验后） |
|---|---|---|
| 副标题 | through **Subgoal Decomposition** | through **Large-Scale Synthetic Data** |
| arXiv | `2308.08381`（**能打开，是别的论文**） | `2405.14333` |
| 年份 | 2023 | 2024 |

### 为什么这条最重要

**如果核验只做「编号能不能解析」，这条会 100% 混进 bib。**

而且它的错误方式是**复合的**：模型把两篇同系列论文的副标题缝到了一起
（「子目标分解」是 V2 的表述），又给了一个格式完全合法、
真实存在、内容无关的编号。**缝合得非常自然**——
自然到如果不做逐字比对，是完全看不出来的。

**这是本次核验里最有价值的一条发现，也是论文正文表 3 的第一行。**

## 五、错误 2：单词级篡改，相似度 0.92

| | |
|---|---|
| v1 | LiveBench: A Challenging, Contamination-**Free** LLM Benchmark |
| 实际 | LiveBench: A Challenging, Contamination-**Limited** LLM Benchmark |

标题相似度 **0.9217**。

**这个数字本身就是知识点**：0.92 落在「人眼会放过、机器阈值也不该卡」的区间。
只有逐字比对（或把阈值提到 0.95 以上，但那会带来大量假阴性）才看得出来。

**值得注意的不是错，是错的方向**：
模型把作者的谨慎表述（limited）换成了更强势的表述（free）。
**这不是随机噪声，是系统性的放大。**

|---|---|

| 实际 | Goedel-Prover: A Frontier Model for Open-Source Automated **Theorem Proving** |

## 七、假警报：**核验器自己错了**

`yue2024mammoth` 被标 PARTIAL，但它的**标题相似度是 1.0、作者也一致**。
一个 1.0 的标题匹配被降级——**这本身就说明判定逻辑有问题**。

查原始记录：arXiv 这条证据的 `year` 字段是空的。

**根因**：`query_arxiv()` 只抓了标题和作者，**没抓投稿日期**，
于是 `year_ok` 恒为 `False`，一条完全正确的记录被判为可疑。

**修法**：

```python
md = re.search(r'<div class="dateline">.*?Submitted on\s+(\d{1,2})\s+(\w+)\s+(\d{4})',
               html, re.S)
year = int(md.group(3)) if md else None
```

### 为什么这条比前三条更值得记

前三条是「**AI 生成的东西错了**」；
这条是「**用来检查 AI 的工具有 bug**」——而且它的表现是**静默的**：
不报错、不崩溃，只是把一条正确的记录标成可疑。

论文第 5.1 节把这条写成了正文论点：

> 核验装置本身也是一个生成步骤，它也需要被检查。
> 一个不可证伪的自动判定不是判定。

## 九、带走的三条

1. **判据的强度决定了能抓到什么。**
   「编号能解析」抓不到「编号合法但内容无关」（错误 1）；
   「标题相似度 0.90」抓不到 0.92 的单词级篡改（错误 2）。
   **设计核验器时先问：「我最怕的那种错误，这个判据抓得到吗？」** 再倒推判据。

2. **检查器自己也要被检查。** 一条 1.0 匹配被降级，那是检查器在报警。
   **要把「反常的判定结果」本身当作信号。**

3. **修正必须留证，且不许「猜一个补上」。**
   一旦允许「猜个正确的填进去」，就等于把未验证的生成结果重新塞回流程。
   流程是：查不到确证就删除，而不是编一个。
   每条修正写进 `refs_corrections.json`，带 v1 值、v2 值和**决定这次修正的证据**。
