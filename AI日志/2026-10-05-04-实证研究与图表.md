## 一、Study A：几乎是白捡的

Study A（引用生成层的错误率）**不需要额外跑任何东西**——
日志 02 的核验过程已经把全部数据留下来了：v1 的原始核验记录、
人工修正表、以及最终确定的三条错误。

要做的事只是**把这三个文件对起来算**：

```
v1 候选 31 → 自动标记 5 → 人工裁定 6 → 真实错误 3 → 9.68%
```

**这带来一个设计上的好处**：Study A 的数字不是「为了写论文去做的实验」，
而是**流程跑完之后自然掉出来的副产品**。这在方法论上更干净——
如果是为了写论文去做，很容易在过程中无意识地把结果往想要的方向调。

脚本 `03_corpus_audit.py::study_a()` 只做一件事：
把 `citation_verification_v1_from_memory.json` 和 `refs_corrections.json` 读进来，
按 `severity ∈ {HIGH, MEDIUM}` 数出真实错误。**不联网，不重新判定。**

## 二、Study B：一次「自动化不够用」的现场演示

### 第一版设计：只看摘要

最初的方案很简单：抓 arXiv abs 页的摘要，用正则扫
`github.com/...`、`open-source`、`our code` 这类模式，有就是「声明白盒工件」。

跑出来 **7/26 = 26.9%**。

但这个数字**明显偏低**，因为很多论文把仓库链接写在正文里而不是摘要里。
如果直接报 26.9%，就是在用「摘要里提没提」冒充「有没有工件」。
**这类替换正是 C1 复盘批评过的那件事**（用容易实现的近似替掉字面要求）。

### 第二版：加一路 GitHub 检索

补一个独立信号：拿论文的「项目名」（标题冒号前的部分）去查 GitHub 搜索 API，
看能不能找到同名仓库。

第一版判定规则写成了：

```python
"name_in_title": norm(it.get("name","")) in norm(title)
```

即「仓库名是不是标题的子串」。结果一眼就不对：

```
cobbe2021gsm8k   → mlcommons/training              （因为标题里有 "Training"）
chen2026lectures → oxford-cs-deepnlp-2017/lectures （因为标题里有 "Lectures"）
```

**假阳性来自于规则太松：短单词在长标题里总是"是子串"。**

### 第三版：改成相似度，并且宁漏勿错

```python
name_sim = _sim(项目名, 仓库名)      # 项目名 = 标题冒号前的部分
desc_sim = _sim(论文标题, 仓库描述)
qualified = (name_sim >= 0.90) or (desc_sim >= 0.70)
```

并且**去掉了「无冒号时退回第一个单词」的逻辑**——
就是它让 `Training Verifiers...` 拿 "training" 去查的。

改完：**8/26**，假阳性清零。

### 但假阴性还在，而且很明显

看被**拒绝**的候选名单，有几条其实是对的：

```
chen2023pot  → TIGER-AI-Lab/Program-of-Thoughts   ns = 0.791  ← 官方仓库，被阈值卡掉
han2022pact  → jesse-michael-han/lean-step-public  ds = 0.659  ← 官方仓库，被阈值卡掉
```

于是对这两条**直接调 GitHub API 取仓库描述和 README 前 1200 字**做证据：

```
TIGER-AI-Lab/Program-of-Thoughts   desc = "Data and Code for Program of Thoughts [TMLR 2023]"
                                   README = "This is code repository for the TMLR2023 paper
                                             [Program of Thoughts Prompting: ...](https://arxiv.org/abs/2211.12588)"
jesse-michael-han/lean-step-public desc = "Proof artifact co-training for Lean"
```

两条都确认是官方仓库。**README 里直接写着 arXiv 编号 `2211.12588`，和论文对得上。**

## 三、从「自动」到「自动＋人工裁定」

到这里已经很清楚：**纯自动筛选在这个任务上做不到可用**。
但**不能因此就把自动结果扔掉、全靠人工判**——那样就没有可复跑性了。

最后定下来的结构是：

```
自动检索（提名）  →  人工裁定（判定）  →  两者都留证据
      ↓                    ↓
  可复跑            可追责（每条都写理由）
```

`artifact_adjudication.json` 里，26 条每一条都有：`tier`（official/third_party/family/none）、
`repo`、`evidence`（证据原文）、`evidence_level`（证据强度）。

其中最需要小心的是 `xin2024deepseekprover` 那条：

```
tier  = family
repo  = deepseek-ai/DeepSeek-Prover-V1.5
理由  = 这是 DeepSeek-Prover **V1.5** 的官方仓库，
        不是所引 V1 论文（arXiv:2405.14333）自身的工件。
        name_sim=0.903 属于「同族不同篇」。
```

如果没有这一步人工裁定，这条会被算成「有工件」，把统计抬高。
**这正是为什么裁定表要逐条写理由而不是打勾。**

## 四、最有价值的一个数：自动筛选的查准率与查全率

人工裁定做完之后，可以算一件两个子研究单独都算不出的事：
**自动筛选相对于人工裁定，准不准、全不全。**

脚本算出来（论文表 4）：

| | 数 |
|---|---|
| 自动标记（两信号并集） | 10 |
| 真阳性 | 8 |
| 假阳性 | 2 |
| 假阴性 | 5 |
| **查准率** | **80.0%** |
| **查全率** | **61.5%** |

**48 小时后回看，这是整篇论文里最有说服力的一个数字。**
因为它用论文自己的工具，把论文自己的论点演示了一遍：

> 自动筛选就是一个 $L_1 \to L_2$ 的归约（仓库页面 → 判定），
> 而这个归约恰好是不可靠的那一环——**同时向两个方向出错**（既误报也漏报）。

而且修复方式是**加一个验证层**（人工对照 README），**不是调阈值**。
调阈值只会把错误从假阳性挪到假阴性——**残余风险被挪动，没有被消除**。
这和论文第 3 节的核心主张是同一件事。

## 五、图表制作

三张图，都用 matplotlib 输出矢量 PDF。

**图 1（框架图）**：手工坐标绘制，不是数据图。
把四段链、三条范式、各自守住的段、以及残余风险画在一张图上。

**图 2（Study A）第一版是双面板**（左：堆叠条；右：失败模式柱状图）。
渲染出来一看有两个问题：左边 x 轴标签被裁掉了；右边所有柱子都是 1，没信息量。

**改成一页「审计漏斗」**：31 → 5 → 3，配上每一步的说明。
**漏斗比堆叠条更贴切**，因为要表达的是**衰减**，
而堆叠条把重点藏在一个很长的轴标签后面。

**图 3（Study B）**：按范式分组的对比柱状图，自动 vs 裁定。

### 一个必须统一的细节

图 3 一开始用的是**摘要筛选**的数字（F 38% / V 0% / R 20%），
但论文表 3 用的是**两信号并集**的数字（F 38% / V 0% / R 40%）。
**两者不一致**，因为 R 范式的 `hendrycks2021math` 是 GitHub 检索命中的、摘要没提。

改法是让图直接读 `official_by_role` 里的 `auto` 字段——
**和表格同源，就不可能不一致**。

### 一个低级的编码错误

第一版图里图注写了中文，渲染的时候 matplotlib 一直在刷：

```
UserWarning: Glyph 26368 (\N{CJK UNIFIED IDEOGRAPH-6708}) missing from font(s) DejaVu Sans.
```

DejaVu Sans 没有中文字形。**论文是英文的，图注本来就该是英文**——
所以这不是"换个中文字体"的问题，是一开始就不该写中文。
全部改成英文标签。

（第 5 节图注里还有一处中文来自 `refs_corrections.json` 的
`failure_mode` 字段，也一并加了英文字典映射，而不是去改那份记录——
**记录是证据，不该为了排版去动它**。）

## 六、这一阶段的自我评估

**做对的**：在发现自动筛选有假阴性之后，**没有把阈值调松**。
调松就会冒出一堆假阳性，把「自动化不够用」这个最有价值的发现掩盖掉。
选择保留严格阈值、用人工裁定兜底，然后**把两者的差距本身当成结果报出来**。

**做错的**：
1. 第一版 `name_in_title` 用「子串」判定，产生了明显的假阳性（`mlcommons/training`）。
   应该一开始就用相似度而不是子串。
2. 图 3 和表 3 的统计口径不一致，是**出完图才发现**的。
   如果一开始就让图和表读同一个字段，这个错误不会发生——
   **这一条已经写成 `04_make_figures.py` 的设计原则**（脚本里没有任何硬编码数据常量）。
3. 图注写中文，属于没想清楚「论文是给谁看的」。

**存疑的**：`artifact_adjudication.json` 里 13 条 official 的证据强度并不齐。
`idavidrein/gpqa`、`wellecks/naturalprover` 这类是**描述与论文标题完全一致**（强证据）；
而 `openai/grade-school-math` 是**靠属主＋数据集名推断**（中等证据）。
虽然每条的 `evidence_level` 都标了，但**没有按证据强度加权统计**。
论文 7.2 节把「只测有没有、不测能不能跑」列为限制，但没提这一条——
**这是本阶段留下的一个已知缺口**。
